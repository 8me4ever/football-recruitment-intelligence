## 4. M2 — 表现引擎 v2（Performance Engine）

**目标**：把旧项目**唯一真正可用的算法**（位置内百分位）工程化，并修正其统计缺陷。

| 项 | 内容 |
|---|---|
| **输入** | M1 的 `player_metrics` + `candidate_pool` |
| **交付物** | `src/features/{percentiles,position_features,contextualisation}.py`、球员画像表 |
| **退出标准** | ① 百分位有最小样本门槛；② 有收缩估计；③ 参考池无重复、无低样本；④ 可输出单球员的完整指标画像；⑤ 有单元测试 |
| **依赖** | M1 |
| **工作量** | 2–3 天 |

### 4.1 保留什么

| 保留 | 理由 |
|---|---|
| `stats.percentileofscore(kind='rank')` 的位置内相对排名 | 符合提示词 Principle 8（不可用同一套原始指标比较 CB 与 ST） |
| "通用指标 + 位置专属指标"的分层结构 | 设计合理 |
| 缺失值 → 中性值 | 方向正确（但需改为"标注 + 中性"） |
| 位置专属指标映射表 | 有领域参考价值 |

### 4.2 修什么

| # | 修正 | 理由 |
|---|---|---|
| 1 | **加最小出场门槛** | 5 分钟出场的球员百分位无意义 |
| 2 | **加收缩估计**（empirical Bayes / 向位置均值收缩） | 出场少的球员应向均值收缩，而非给出极端百分位 |
| 3 | **参考池去重 + 排除低样本** | 52 行重复 + 75/88 行低样本扭曲分位数 |
| 4 | **并列值处理** | 大量 0 值指标的 `kind='rank'` 会产生伪高分 |
| 5 | **移除 `CrdY`/`CrdR` 作为"表现"正向指标** | 足球逻辑反向（牌多≠表现好） |
| 6 | **引入门将 advanced 指标**（PSxG、PSxG±、Sweeper #OPA、Crosses Stopped） | 数据已存在但旧系统零使用 |
| 7 | **扩充特征集** | 旧系统每位置用约 15 个指标，可用 101 个中有大量未用（`PrgR`、`CPA`、`Mis/Dis`、分区域 Tkl、传球分档） |
| 8 | **补充 possession 调整与 per-90 口径** | 球队控球风格会影响绝对计数指标 |

### 4.3 明确不做

- ❌ 不做"表现分"的单一合成（旧项目的"加权表现分"权重无据）。M2 只产出**多维度画像**；
- ❌ 不引入 UMAP / 复杂嵌入（提示词 §16）；
- ❌ 不做"表现好→不易离队"的假设绑定。

## 6. M4 — 离队风险（风险评分版，非概率）

**目标**：把旧项目唯一"像模型"的组件重建为**诚实、透明、可用**的风险评分。

| 项 | 内容 |
|---|---|
| **输入** | M1 数据、M2 画像、M3 评估 |
| **交付物** | `src/departure/{features,model,calibration}.py`、风险评分报告 |
| **退出标准** | ① 输出**明确标注为评分，非概率**；② 每个分项可解释；③ 带样本充分性标注；④ 有时间外评估；⑤ 有诚实基线对比 |
| **依赖** | M1、M2、M3 |
| **工作量** | 2 天 |

### 6.1 关键决策：先做路线 A（透明评分），不做路线 B（真概率）

| 路线 | 内容 | 可行性 |
|---|---|---|
| **A（推荐，立即做）** | `Departure Risk Score ∈ [0,100]`，由领域先验加权：合同紧迫度 + 年龄阶段 + 出场稳定性 + 表现位次。附敏感性分析 | ✅ 可立即实现 |
| **B（后置）** | 正则化逻辑回归，输出**校准概率**（校准曲线 + Brier） | ❌ 需 ≥200–300 个"球员-赛季"观测；当前只有 25+27=52 |

**输出格式建议**（提示词 §11 M4 要求）：

```
球员           ：Stefano Sensi
风险评分        ：62 / 100   （评分，非概率）
样本充分性      ：⚠️ 低（出场 46 分钟，不足 450 分钟门槛）
主要驱动因素    ：
  · 合同剩余     0 年（2024 到期）        +25
  · 出场时段     边缘轮换（联赛第 78 百分位之外的分钟数）+20
  · 表现位次     中场第 42 百分位          +10
  · 年龄阶段     27 岁（当打期）           +7
不确定性        ：评分区间 [50, 74]（基于分项敏感性）
```

### 6.2 必须修的旧系统错误

| # | 旧错误 | 修正 |
|---|---|---|
| 1 | 称"probability"但从未校准 | 改名"风险评分"，或做真校准 |
| 2 | 合同项恒为常数 2.0 | **真正接入**合同数据（含租借处理） |
| 3 | `CrdY/CrdR` 越多越"好" | 移除或反向 |
| 4 | 年龄 30 岁设为风险峰值 | 重新论证；实测年龄与离队 r=−0.008, p=0.969 |
| 5 | clip 到 [0.05, 0.95] 造成假精度 | 改为评分区间 + 不确定性 |
| 6 | 参数来自伪造优化 | 改为领域先验 + 敏感性分析 |
| 7 | 输出 4 位小数 | 按样本充分性给出合理精度 |

## 7. M5 — 阵容脆弱度（Squad Vulnerability）

**目标**：回答"哪个球员离队最伤？"——这是旧系统**完全缺失**的新层。

| 项 | 内容 |
|---|---|
| **输入** | M4 的离队风险、M2 的球员画像、M1 的阵容数据 |
| **交付物** | `src/squad/{depth,vulnerability,needs}.py`、阵容脆弱度排行 |
| **退出标准** | ① 三个子指标各自可解释；② 组合方式可论证；③ 有人工校验的样例 |
| **依赖** | M4 |
| **工作量** | 2–3 天 |

### 7.1 概念模型（提示词 §11 M5）

```
阵容脆弱度 ≈ 离队风险 × 球员重要性 × 替代难度 × 深度风险
```

⚠️ **不要直接硬编码这个乘法式**（提示词明确要求）。应先评估可行的定义：

| 子指标 | 可行定义（基于现有数据） | 数据支持 |
|---|---|---|
| **球员重要性** | 该球员占同位置总出场时间的比例 + 其表现分位 | ✅ 有 `Min`、百分位 |
| **替代难度** | 市场上相似画像球员的稀缺度（需要 M7/M8 先完成）→ M5 先用**同位置同队深度**近似 | ⚠️ 完整版依赖 M8 |
| **深度风险** | 同位置、同队中达到表现门槛的球员数（如 <2 人 = 高风险） | ✅ 有 |
| **离队风险** | M4 输出 | ✅ |

**建议**：M5 先做一个**透明加权和**（而非乘法），并展示每个分项，让用户自己判断权重是否合理。

### 7.2 需要的领域决策

- 什么是"同位置"？只看 `primary_position` 还是看 `positions_all`？
- 国际米兰的三中卫体系下，`DF` 里实际包含 LCB/CB/RCB 三种角色 → **这直接依赖 M7 的角色画像**
- 说明 M5 的完整版应在 M7 之后做一次更新

| **退出标准** | ① 可行性先于实现；② 角色**可解释、可命名**；③ 有稳定性检验（重采样后角色是否稳定）；④ 角色数由数据决定而非人为指定 |
| **依赖** | M1、M2（可与 M3–M6 并行） |
| **工作量** | 3–5 天 |

### 9.1 第一步必须是可行性评估（不写建模代码）

| 评估项 | 现状 | 结论 |
|---|---|---|
| 指标是否足够刻画角色？ | 101 个去重指标；但**缺少关键角色区分指标**：触球区域分布（有 `Def/Mid/Att 3rd`、`Att Pen`）、传球距离分布（有 Short/Medium/Long）、带球（`PrgC`、`Carries`）、推进（`PrgP`、`PrgDist`） | 🟡 **基本支持**，但**没有位置坐标数据**（FBref 免费数据无 x/y 事件坐标） |
| 样本量是否足够聚类？ | 每赛季约 430 名可用球员（Min≥450） | ✅ 足够 |
| 位置内样本是否足够？ | 门将仅约 45 人、前锋约 100 人 | ⚠️ 门将角色可能只能分 2–3 类 |
| 是否有战术/体系信息？ | ❌ 无阵型、无球队风格 | ⚠️ 无法区分"因体系而表现出某特征"与"球员本身风格" |
| 能否做稳定性检验？ | ✅ 可通过 bootstrap 重采样 | ✅ |

**诚实预判**：**没有位置坐标数据**意味着无法做真正的"角色"划分（如区分内切型边锋 vs 贴边型边锋需要触球热区）。**可行的替代**是基于**行为统计分布**的角色聚类（如"高传球量+高传球距离"→ 组织型；"高带球推进+高被侵犯"→ 突破型）。必须在文档中说明这一限制。

### 9.2 方法路线（由简到繁，逐级评估）

| 阶段 | 方法 | 何时采用 |
|---|---|---|
| 7a | **规则辅助**：用少数关键指标的阈值组合手工定义角色 | **先做**（最可解释） |
| 7b | PCA → 解释主成分 | 若 7a 无法覆盖，用 PCA 找出主要变异方向 |
| 7c | KMeans / GMM 聚类 | 若 PCA 显示清晰簇结构 |
| 7d | UMAP 可视化 | **仅在需要展示时**（提示词 §11 提到，但 §16 要求不必要不引入） |

⚠️ **不引入 UMAP 作为默认依赖**；先试 PCA。

## 10. M8 — 相似度与候选排序（Similarity & Ranking）

**目标**：回答"谁最像他？"以及"谁不只是像，而是更好？"

| 项 | 内容 |
|---|---|
| **输入** | M6 的候选池与需求、M7 的角色 |
| **交付物** | `src/recruitment/{candidate_pool,similarity,ranking,uncertainty}.py`、候选短名单 |
| **退出标准** | ① **风格相似度与质量水平严格分开**；② 排序理由可解释；③ 每个推荐带不确定性；④ 明确声明候选池仅限意甲 |
| **依赖** | M6、M7 |
| **工作量** | 3–4 天 |

### 10.1 核心要求：区分"风格相似"与"质量更好"（提示词 §11 M8/M9、Principle 9）

这是最容易被做错的地方。必须输出**两个独立维度**：

```
相似度（风格）  ：cosine similarity on standardized role features   ∈ [0, 1]
质量水平        ：该位置内的表现分位（与相似度无关的独立量）      ∈ [0, 100]
```

于是候选分为四类，而不是一个混合分数：

|  | 高相似度 | 低相似度 |
|---|---|---|
| **高质量** | ✅ **升级型替代**（首选） | ⚠️ 不同类型但更强（可能是战术变革） |
| **低质量** | ⚠️ 纯风格复制（不推荐单独使用） | ❌ 不相关 |

**必须避免**：不要输出 "Fit = 87.43%" 这类单一混合分数（提示词 §11 M12 明确禁止假精度）。

### 10.2 基线方法优先

| 顺序 | 方法 | 说明 |
|---|---|---|
| 1 | 标准化特征距离 / cosine similarity | **先做这个** |
| 2 | KNN 检索 | 直接用 1 即可 |
| 3 | PCA 嵌入后再算相似度 | 若原始特征共线性太强 |
| 4 | 角色条件相似度（只在同角色内比较） | 与 M7 结合 |

⚠️ 不引入"learned metric"（提示词 §11 提到，但需监督信号，当前数据不支持）。

### 10.3 候选排序的维度（提示词 §11 M9）

```
Role Fit        ← 角色契合（来自 M7/M8）
Performance     ← 质量水平（来自 M2）
Age             ← 年龄与年龄曲线位置
Development     ← 发展空间（M11 后置时，先用年龄近似，并标注为近似）
League Context  ← ⚠️ 只能声明"同联赛"，因为只有意甲
Risk            ← 不确定性（来自 M10... 即本文档的"不确定性"组件）
```

**禁止**：不做性价比（无转会费/薪资数据）。

## 15. 实施纪律（贯穿所有里程碑）

从旧项目的错误中提炼的铁律：

| # | 纪律 | 对应旧项目的错误 |
|---|---|---|

| 2 | **任何性能数字必须附样本量、置信区间与基线** | 只报单点 0.9275 |
