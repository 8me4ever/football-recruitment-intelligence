## 1. 项目从哪里开始

这项工作最初属于“以 Data Scientist 身份进入职业足球”的个人作品集规划。此前对话将**球员招募与阵容规划系统（Recruitment & Squad Planning Intelligence System）**列为优先级最高的项目，因为它和俱乐部的实际决策流程接近，也能承接用户早年在欧洲留学时完成的 Inter Milan 毕业设计。

旧项目的主要问题是预测国米球员离队或留队。新项目的目标更广：依据球队阵容和球员表现识别补强需求，从候选球员中形成一份有证据、可解释的考察名单。离队分析可以作为一种风险输入，但不是新项目的中心，也不是必须复用的模型。

此前的求职规划对话也单独讨论过第二个作品集方向“Off-Ball Spatial Value Intelligence”。它使用 SkillCorner tracking data，和本项目是两项独立工作；下文进度只记录 Recruitment & Squad Planning，不把第二项目的 PRD/阶段计划混入中超采集状态。

## 2. Inter 毕业设计审计与可复用基础

旧项目文件现已归档在 `archive/msc-inter-departure-2025/`。审计确认，它包含可复用的足球数据清洗、位置归类和候选池构造经验；但离队标签样本很少，不能把旧输出直接当作经过校准的“离队概率”。意甲样本也不能回答中超国安的补强问题。

在新仓库中，原型的数据层曾按 FBref 的意甲球员数据重建。三个赛季清洗后分别有 577、590、599 名球员；跨队赛季中转球员按球员聚合，保留多位置，标记低出场样本，并把缺失、租借和真实零值区分开。M1 处理了旧代码的表头偏移、重复计数、静默吞错、位置丢失等问题。相关产物见根目录 `README.md` 与 `reports/analysis/M1_data_quality_report.md`。

这部分证明了数据工程和旧项目审计能力，**并不代表中超项目已经完成 M1 或建立可用的中超表现模型**。旧版 M0–M9 路线图是意甲原型的阶段标签，后续中超工作采用 `C0–C5` 独立跟踪。

## 3. 为什么转向中超与北京国安

用户的职业目标是在中国足球行业寻找相关工作，因此决定把主要案例从 Inter Milan 改为北京国安，以中超球队作为候选比较池。北京国安是深入分析对象；若将来制作整个联赛的候选池，数据采集仍需覆盖中超球队及符合范围的洲际赛对手，不能只保留国安球员。

项目要回答的是：在明确的决策日期和证据范围内，国安哪些位置可能需要补强？哪些球员值得进一步考察？最终预期成果包括阵容需求报告、5–10 名长名单、3 名候选人的深入比较、视频证据、局限说明和可复现代码。

已确定的分析边界：

- 表现质量、风格相似度、国安需求匹配分开呈现。
- 预算、工资、合同和伤病数据缺失时，不宣称某项转会“买得起”、交易可行或球员不存在伤病风险。
- 没有位置坐标时，不声称计算了真实推进距离、热区或完整战术角色。
- 不提前指定补强位置；应先基于阵容使用、年龄和表现等证据诊断需求。
- **2026 中超是主决策数据**，用于描述决策日前国安当前阵容、出场使用、球员表现和候选人近况。
- **2025 中超是历史参照数据**，用于评估跨赛季稳定性和单季波动；它不决定当前阵容诊断。此前缺失的37场已补采，目前240场完赛赛事都有通过验收的球员统计表。
- 2024 数据可得性需另行核实，当前不承诺纳入。
- 进入 C2 前必须冻结具体决策日期和数据 cut-off，排除晚于 cut-off 的信息。

这些决定记录在 [`CSL_PROJECT_BRIEF.md`](CSL_PROJECT_BRIEF.md)。

## 4. 数据源选择与网页采集决策

中足联可见公开数据的颗粒度不足以支持逐场球员招募分析；用户没有 Wyscout 从业访问权限，因此提出用 WhoScored 或 Sofascore 网页数据。经过可行性调研，项目决定先以 Sofascore 的可见比赛页和球员表为目标，并按用户指定使用 Scrapling 与浏览器渲染 DOM 获取数据，而不是把 API 接口当成采集方案。

用户已明确说明所属职业俱乐部取得了 Sofascore 官方授权。该授权是本项目的用户提供前提；采集方向因此不以重新取得许可为阻塞项。工程方案仍按约定仅读取已渲染网页的可见 DOM、表格和对应无障碍属性，不主动调用数据 API，不把网络响应或页面应用状态作为统计数据源。

先前可行性验证使用 Scrapling 0.4.15、Playwright 1.63.0、系统 Chrome、1440×1000 桌面视口、`en-GB` 与 `Asia/Shanghai`。比赛页起始时没有统计 HTML 表格；点击比赛阵容区域的 `Player stats` 后才显示球员表。六个分类为 `General`、`Attacking`、`Defending`、`Passing`、`Duels` 和 `Goalkeeping`。球员 ID 从球员链接读取，球队从队徽 `img.alt` 读取，评分从 meter 的 `aria-valuenow` 读取。

三个早期比赛样本已抓到球员表；其中一场保存了全部六分类，共 95 条球员比赛行。该报告验证了小样本网页提取和离线解析能力，不证明浏览器路线覆盖了所有页面，也不代表全赛季已完成。详见 [`CSL_SCRAPLING_FEASIBILITY.md`](../reports/analysis/CSL_SCRAPLING_FEASIBILITY.md) 与 [`CSL_SOFASCORE_SCRAPLING_EXECUTION_PROMPT.md`](CSL_SOFASCORE_SCRAPLING_EXECUTION_PROMPT.md)。

## 5. 2025 中超赛季采集

在网页小样本和采集器阶段性开发后，2025 中超建立了 240 场唯一完赛赛事清单。早期直达比赛链接的路线有37场失败；本轮改为从赛季页选中可见轮次，再点击精确的完赛赛事卡片，已补齐全部失败场次。当前机器审计记录：

| 项目 | 结果 |
|---|---:|
| 赛程唯一比赛 | 240 场 |
| 通过身份及六分类验收 | 240 场 |
| 未取得球员表 | 0 场 |
| General 球员比赛记录 | 7,417 条 |
| 不同球员 ID | 452 人 |
| 北京国安球员表 | 30 / 30 场 |

240 场均通过赛程卡片事件 ID、可见日期与比分、比赛页标题球队、分类表球队和球员 ID 检查；六类均有表格，五个非门将分类的球员 ID 集合逐场一致，门将分类只收录 General 球员集合中的门将。原先35场错误落到其他赛事/日期的问题由精确卡片点击消除；另2场等待比赛详情和统计标签水合后也成功采集。因此球员统计比赛覆盖现为**240/240**，不再是部分覆盖。

重要的流程教训是，旧比赛 slug 可能解析到同一对阵的更新赛事；HTTP 200 或球队名称吻合都不能证明读到了目标年份。当前可复用链路是赛季页 → 可见轮次 → 精确赛事 ID 卡片 → 等待比赛标题与 `Player stats` 分类水合 → 六分类验收。脚本与新增重试证据见 `scripts/retry_csl_2025_failed_card_click.py`、`data/csl/season_2025/player_category_dom_retry.jsonl`、`data/csl/season_2025/collection_audit.json` 和 [`CSL_2025_COLLECTION_AUDIT.md`](../reports/analysis/CSL_2025_COLLECTION_AUDIT.md)。

## 6. 2026 赛季范围与当前成果

2026 的范围是在用户明确要求后确定的：收集中超球队的联赛比赛；同时纳入有中超球队参赛的亚冠精英联赛或亚冠二级联赛比赛，并保留该场双方球队的球员数据，以便保留对手背景；不收足协杯。洲际比赛的更高权重应在后续分析中处理，而不是写进原始数据。

截至 2026-09-26，国安网页可见比赛清单留存 **27 条目标范围记录**：25 场完赛中超、1 场延期中超、1 场完赛亚冠精英联赛；已排除 3 场足协杯。赛事 ID、赛季 ID、日期和事件 ID 已记录在 `data/csl/season_2026/guoan_fixtures_observed_2026.csv`。这只是国安当前可见赛程快照，不是整个联赛完整赛程，也不是 2026 赛季最终赛程。

此前先核验了 **2026-09-05 上海海港 0–0 北京国安，事件 ID 15552633** 的内置浏览器六分类 DOM 样本。这份样本帮助确认视口、赛程卡片、`Player stats` 入口和表格字段；它仍是独立采集的对照证据。

2026-09-27 继续完成了国安快照中的全部 **26 场完赛赛事**：25 场中超、1 场亚冠精英联赛。独立 Scrapling `DynamicSession` 从国安 Finished 赛程卡片进入比赛，逐场采集六分类可见 DOM；唯一未出现在独立赛程分页的 3 月 14 日鲁能—国安场次使用直达比赛 URL，并通过同样严格的身份与六分类验收。原始记录在 `csl_2026_capture/scrapling_raw/`，`data/csl/season_2026/guoan_collection_audit.json` 显示 26/26 场通过、无缺失，标准导出 `guoan_player_match_stats_2026.csv` 含 **791 条球员比赛记录**。27 条范围记录中的延期中超比赛未计入完赛数据。

内置浏览器另存有 26 场相同范围的原始表，审计导出为 `guoan_player_match_stats_2026_in_app.csv`。独立 Scrapling 与内置浏览器按比赛 ID 和球员 ID 对齐后，791 条记录的六分类字段、分钟、位置和评分逐字段一致。最早的海港—国安完整样本 `csl_2026_capture/browser_dom/15552633_5322e40a7210.json` 保留为路线发现证据；`15552633_7023020d314d.json` 是未通过完整六分类的早期版本。

**同日的后续赛程核对更正了上面的专属快照口径：** 与全赛季 `fixtures_2026_in_scope.csv` 和规范球员比赛导出逐场对照时，发现第1轮武汉三镇 0–2 北京国安（`15551889`，2026-03-08）已在全赛季数据中通过采集，但未进入旧 Guoan 专属 fixture ledger。现已将其加入最新 ledger，使用保存的 Scrapling 可见 DOM 重跑独立审计，结果更新为 **27/27场完赛赛事通过（26场中超、1场亚冠精英），823条双方球员记录**。原26场内置浏览器审计输入清单已单独归档为 `data/csl/season_2026/guoan_in_app_fixture_snapshot_2026-09-27.csv`，其旧结果仍保持791行；不将两个不同范围伪装成完全对照。

## 7. 2026 采集阻塞与修复复盘

### 2026-09-27：全中超与相关亚冠采集完成

用已验证的“赛季赛程页 → 可见轮次 → 精确赛事卡片 → 比赛详情 → Player stats → 六分类 DOM 表”的 Scrapling 链路扩展到全范围。中超赛事页 30 轮留存 243 个唯一事件卡片（208 完赛、32 未赛、3 延期）；亚冠精英 26/27 赛季留存 16 场、亚冠二级 26/27 赛季留存 6 场至少包含一支 2026 中超球队的赛事。全范围台账共 265 场。

截至 2026-09-27，211 场已完赛目标赛事全部经独立 Scrapling 六分类采集，并对原始 HTML 离线重解析：中超 208/208、亚冠精英 2/2、亚冠二级 1/1，合计 **6,503 条球员比赛记录、474 个唯一球员 ID、0 场缺漏**。19 场未赛亚冠、32 场未赛中超和 3 场延期中超仍在赛程清单，不计入完赛数据。规范化导出、逐场覆盖表和机器质量报告分别是 `data/csl/season_2026/player_match_stats_2026.csv`、`collection_coverage_2026.csv`、`data_quality_report_2026.json`；原始网页 DOM 在 `csl_2026_capture/scrapling_raw/`。具体入口、选择器、身份规则和重跑命令见 [`data/csl/season_2026/COLLECTION_RUNBOOK_2026.md`](../data/csl/season_2026/COLLECTION_RUNBOOK_2026.md)。

上述结果是截至页面观测日的全部已完赛赛事，不代表 2026 赛季最终赛程。2025 历史层和当前正式流程基准重采现均已取得完整比赛统计覆盖；C0 七项 Gate 已按章程逐条审核并通过。正式 C1 仍需补全决策日球员阵容/效力时间表、名义位置与缺失值语义。

上一轮把 2025 的脚本改成 2026 pilot 后，独立 Scrapling 浏览器连续遇到两个不同问题：

1. 使用 `data/csl/season_2026/browser_profile` 启动 Chrome 时，系统明确报出 F 盘配置目录 `Crashpad/settings.dat` 和 Chrome lock file 创建被拒绝，进程退出。关闭 Chrome 后，普通沙箱重跑仍报拒绝访问；在获准沙箱外执行后，Chrome 可以启动。因此本次得到的证据指向本地执行权限/文件访问限制，不足以说明是用户浏览器占用了该 profile。
2. 获准运行后，Chrome 收到 HTTP 200，但比赛页在 30 秒内只有 Sofascore 通用页眉和页脚。球队页通过独立会话加载时也缺少可用的比赛控件。与此同时，用户的内置浏览器在相同比赛上能显示完整页面，且点击国安赛程卡片后能进入正确比赛并加载球员表。两种浏览器会话的加载结果不同；目前还没有证明是登录态、headless 模式、网站状态或某一项浏览器配置造成。

旧 pilot 还有固定等 5 秒、硬编码比分空格、没有把六分类是否通过作为最终状态条件等问题；这些逻辑不能用于批量验收。9 月 27 日复测发现独立浏览器已能显示国安 Finished 赛事列表，旧探针失败于 `a[href]` 同时匹配赛事卡片与页面底部空链接，属于选择器歧义。限定到 `#tabpanel-list` 中含 `FT` 的卡片后，独立 Scrapling 成功进入海港—国安比赛并提取六分类；随后在国安 26 场完赛范围完成批次。新采集器按分类专属表头和球员行等待，逐场验收身份与球队集合，保留失败页面和断点续跑状态。3 月 14 日场次从直达页取得，但只有在 URL、日期、赛事、双方、比分、六分类和球员 ID 全部通过时才被接纳。

本轮也更正了 README 中“内置浏览器占用 Scrapling profile”与“网页跳到首页”的先前无充分证据断言。
